Hash routing that respects the Back button

The first version deep‑linked files with ?file=About.md and history.replaceState. It worked, but replace writes no history entry, so browser Back and Forward did nothing. Opening five files and hitting Back left you on the same file.

Switch to the hash

The canonical location is now the URL hash — #/Experience.md, or #/ for the welcome screen. Setting location.hash pushes a real history entry, so Back and Forward move through the files you opened. A single hashchange listener re‑opens whatever the hash points at.

Break the feedback loop

The catch: setActive() writes the hash, and the hashchange it triggers would call setActive() again. Two guards handle it: 

suppressHash   # set while the hashchange handler runs, so its openFile() writes nothing
p === active   # the handler bails early when the hash already matches the open file

During start‑up a booting flag makes every write a replaceState instead of a push, so the first load never leaves a dangling entry.

Keep the old links working

?file= URLs are still honoured once, on load: the value is resolved, the query param is stripped with replaceState, and the app settles on the hash form. Old bookmarks keep working; new ones are clean.

Cost of the whole feature: about 30 lines, one event listener, two booleans.
