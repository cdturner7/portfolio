Faking an IDE with Spring Boot and vanilla JS

The whole site is one page dressed up as IntelliJ IDEA. There is no SPA framework and no build step for the front end — just a Spring Boot server, Thymeleaf fragments, and a single hand‑rolled ide.js.

The tree is server data

A ProjectStructure bean holds the fake project tree and a flat path → node map. The home controller renders the tree into the left tool window server‑side; nothing about the file list is decided on the client. 

root.add(ProjectNode.file(
    "Skills.json", "Skills.json", "json", "JSON",
    "pages/skills :: content"));   // the Thymeleaf fragment to serve

Opening a file is a fetch

Clicking a tree row or a tab calls openFile(path). The pane for that path is created once, then /content?path=… is fetched and the returned fragment is dropped in with innerHTML. Subsequent opens just un‑hide the cached pane, so switching tabs is instant and the server is hit at most once per file. 

GET /content?path=Skills.json
→ ContentController.findByPath("Skills.json").getFragment()
→ "pages/skills :: content"   # Thymeleaf renders just that fragment

Because fragments arrive as a string and go in through innerHTML, any <script> inside them never runs. Panes that need behaviour (the JSON tree, the resume viewer, the contact form) are wired from ide.js with delegated listeners on the pane host instead.

State lives in localStorage

Open tabs and their order, the active file, folder collapse state, panel widths, the theme, the terminal — all of it is written to localStorage under an ide.* namespace, so a refresh drops you back exactly where you were. The URL hash carries the active file on top of that, which is its own note.

Trade‑off: no framework means no free reactivity, so every view has an explicit render* function. For a surface this small that is a feature — the data flow is completely legible.
